6 脚ロボットのサンプル、配布パッケージ prj4 について

※
(重要) 以下の説明ですべて大文字の文字列 $WS, $YOU, $VERSION などは
自分の環境に合わせた適切な名前に読み替える。
$YOU, $USER はユーザのアカウント
$WS, $ROSWS は ROS のワークスペース
$VERSION は ROS の version, 現在は noetic
$DOWNLOAD はパッケージのファイルをダウンロードしたディレクトリで、
  通常は ~/ダウンロード または ~/Downloads となる。
を表す。
  
prj4 はプロジェクト名(project 4)を表す。ロボットに指示を送る C++
のプログラムは prg4 (program 4)となる。似ているが間違えないように
気をつける。

※
(重要) Linux のシステムが所有するディレクトリ (/usr/...) での
作業 (ln -s など) には管理者権限が必要になるので、適宜 sudo を付けて
実行する。

実行するコマンドを記述するときには行頭に $ を記す。次行はその例、
$ catkin_make

ディレクトリの表し方は以下のようになる。プロジェクト prj4 の
説明の文書ファイル（このファイルも含む）が置かれる場所に移動
するコマンドは以下になる。
$ cd /home/$YOU/$WS/src/prj4/doc
$ cd ~/$WS/src/prj4/doc
この2行は同じ意味になる。なお一連の README*.txt の説明では前半を
省略して以下の形で記述することもある。
prj4/doc

このファイルに記述されていない補足的な情報が記載された
READMEmisc.txt が ~/$WS/src/prj4/doc にあるので、
基本的な使い方を理解したらそちらにも目を通しておくとよい。

自分で作ったプログラムを配布パッケージに簡単に統合する
手順は ~/$WS/src/prj4/doc/READMEprogramming.txt の最後の部分、
および ~/$WS/src/prj4/src/lessonneo.cpp の冒頭部分を見る。

1回目のインストールの仕方

※ 既に古いパッケージが存在している場合は次の「2回目以降」を見る。

パッケージ prj4.202?????.tgz の展開の仕方と最初の設定

※
以降の説明ですべて大文字の文字列 $WS, $YOU, $VERSION, $DOWNLOAD
などは自分の環境に合わせた適切な名前に読み替える。
$付きの名前をコピペしてそのまま書いてはいけない!!!

パッケージのファイル prj4.202?????.tgz を ~/$DOWNLOAD に
ダウンロードしておく。

事前に用意した ROS の workspace を仮に ~/$WS とする。
workspace の作成の仕方がわからない場合は以下を見る。
---------- workspace の作成、ここから --------------------------
例としてホームディレクトリ直下に abc という名前で作成する場合
$ cd
$ mkdir -p abc/src
$ cd abc/src
$ catkin_init_workspace
$ cd ..
$ catkin_make
これで ~/$WS は ~/abc を表すことになる。
---------- workspace の作成、ここまで --------------------------

パッケージのファイルを ~/$WS/src/ に移動させる。
$ cd ~/$WS/src
$ mv ~/$DOWNLOAD/prj4.202?????.tgz .
ファイルを展開する。
$ tar zxvf ./prj4.202?????.tgz
すると ~/$WS/src/prj4 ができる。

2024年4月から各種設定を自動で行うスクリプトが利用できるようになった。
$ cd ~/$WS/src/prj4
$ ./prj4init.sh
この操作で
world, urdf, sdf, stl
に関する設定が自動で行われる。設定内容の詳細は
READMEinit.txt
に記載されている。

次のコマンドで .bashrc の設定を有効にできる。次からターミナルを
起動すると自動的に設定されるので、手動で実行する必要はなくなる。
$ source ~/.bashrc
ワークスペースを変更する時はこの操作が必要になる。

2回目以降のインストールの仕方

今まで使っていたワークスペースを継続して使い、
インストール済の古いパッケージの代わりに、配布された
新しいパッケージやバックアップしてあったパッケージを使用する手順

事前に今まで自分が作ったプログラムやファイルのバックアップを
作成しておくことを推奨する。手順は以下になる。
20240419の部分は日付を表すので、バックアップを作成する日に置き換える。

バックアップファイルの作成方法
------------------
$ cd ~/$WS/src
$ tar zcvf ./prj4.20240419.tgz ./prj4
------------------
このようにバックアップの圧縮ファイル
prj4.20240419.tgz を作って別の場所や外部のUSBメモリ、cloud ストレージ
などに保存しておけば、なんらかの障害で以前のパッケージの状態に
戻したい時など必要なときに過去の状態を再現できる。

その後、古いパッケージ prj4 は次のように削除するか、
$ cd ~/$WS/src
$ rm -r ./prj4
またはワークスペースの外に移動させる。
$ cd ~/$WS/src
$ mv ./prj4 ~/

新しいパッケージを ~/$WS/src に置く。手順は1回目のインストールを
参考にする。

※
バックアップしてあったパッケージを「新しい」ワークスペースで
使う場合は1回目のインストールの手順になる。

※ 202604
ワークスペースは同時に複数個保持することが可能である。ただし同時に
複数個使用、実行することはできず、1個に限られる。どのワークスペース
がアクティブになるかは ~/.bashrc 末尾で「最後に」指定される
source ~/$WS/devel/setup.bash
中のワークスペース $WS になる。source ~/$WS/devel/setup.bash を
変更することで使用するワークスペースを切り替えることができる。

実行ファイルのビルド

実行ファイル prg4 をビルド(実行ファイルを作成)する。まず $WS に移動する。
$ cd ~/$WS
-----
※  2022年6月以降のプログラムの動作で、６脚とNextageで異なる部分が
生じたので、今後配布するパッケージでは使うモデルの種類を

#define MODEL_6LEG
// #define MODEL_NEXTAGE
自分が使わない方のモデルをコメントアウトして無効にしてから
次のコマンドを実行する。

$ catkin_make

ここまでできたら

$ cd ~/$WS

$ catkin_make clean
$ catkin_make

その後 rviz, gazebo を実行する。

rosrun は起動中のプロセスがあればそのまま実行を続けてもよい。

サンプルプログラムの動かし方

(1) rviz で関節の動きを確認する。

※ これは必須ではないので、何か問題があればスキップして (2) に進んで
  構わない。

$ cd ~/$WS
$ roslaunch prj4 prg4_rv.launch          (melodic, noetic の場合)
$ roslaunch prj4 prg4_rv.launch.kinetic  (kinetic, indigo の場合)

$ sudo apt upgrade

$ cd ~/$WS
catkin_make で実行ファイルを生成する。
ここまでの作業で実行済ならスキップしてもよい。
ただし今後プログラムを書き換えたときはその都度この指示が必要になる。
$ catkin_make

エラーが表示されて Gazebo やプログラムが実行できない場合の対処法

・エラーの原因が表示される場合はその内容を参考にして間違いを修正する。

$ rosrun prj4 prg4

で実行すると、途中でエラーとなり異常終了してしまう場合は、
src/*.cpp, *.h プログラムの何処かが間違っている可能性が高い。表示される
エラーメッセージを読んで何が問題となっているのか理解するように努める。

プログラムが間違っている場合は修正するデバッグの作業が必要となる。
単純な間違いであれば、
最初は printf() をプログラム中の怪しそうな場所に挿入して、その時点の
変数の値などをチェックすると問題点を見つけられる可能性がある。

どこが間違っているか見つけるのが難しそうな場合は、
デバッガ gdb を使うとどこに問題があるかを短時間で特定できる。

gdb を使用するときは次のようにコンパイルと実行を指定する。
通常は、
$ catkin_make
$ rosrun prj4 prg4
であるが、次の指定をすることでデバッガの管理下で実行できる。
$ catkin_make -DCMAKE_BUILD_TYPE=Debug
$ rosrun --prefix 'gdb' prj4 prg4

途中でエラーが生じるとそこで実行が中断され、プログラムのどこで
止まったか表示される。
中断したら gdb の機能を活用して様々なことを調べることができる。
gdb の基本的な使い方は、
https://edu.isc.chubu.ac.jp/naga/rp2/rp23.html
にある。
インターネットで検索すると他のより詳しい資料も見つけられる。


稀に明らかに間違いではないのにエラーが表示されて実行できないことがある。
その場合は、

・ setup.bash が正しく実行されているか確認する。手動で実行してみる。
$ source /opt/ros/$VERSION/setup.bash
$ source ~/$WS/devel/setup.bash

~/.bashrc に setup.bash が自動で実行されるように以下のようにファイル末尾
に記述されているか確認する。
source /opt/ros/$VERSION/setup.bash
source ~/$WS/devel/setup.bash
なお自分が作成した「複数」の $WS の setup.bash を実行する場合、
「最後」に書いてあるものが有効なので、確認する。

・同じ名前や内容のパッケージが別の場所に置いてある。
この場合、勘違いして別の場所にある同名のファイルを編集したり
catkin_make の対象と思い込んでしまうことがある。その場合、書き換えた
内容が結果に全く反映されない現象が見られる。また $WS に別名の
パッケージがあって、その中の設定ファイルや実行ファイルに同じ名前の
ものがあると、別のパッケージに含まれる設定ファイルや実行ファイル
の方が読み込まれたり実行されるケースがある。
明らかに結果が変わるはずの変更が結果に反映されない場合は、これらの
ケースを疑ってみる。
対処法は同名のパッケージを複数同時に所持しない、一つの $WS に複数の
パッケージを配置しないようにする。

・Gazebo は稀に間違っていなくても動かないことがあるので、確実に
動くはずと思うときは複数回起動してみる。また起動に極端に長い時間が
かかることもあるので、エラーメッセージが表示されない場合はしばらく
待ってみる。

・ターミナルを終了して、新たに起動したターミナルで動かしてみる。

・一旦ログアウトして、再度ログインした環境で試してみる。

・一旦電源を落として、再起動した環境で試してみる。実際にこれで直った
ことがある。

・Ubuntu のソフトウェアの自動更新の機能で、更新できるものがあれば
更新してみる。ROS関連のソフトウェアを最新にすると直る可能性がある。

制御プログラムの解説

main() の処理では、ロボットの動作、制御に必要な処理をオブジェクトの生成や
タイマーによる処理として登録したあとは最後に ros::spin(); を呼び出して、
以後の処理は ROS の制御下に渡してしまう。よって、通常のプログラムで
あるような、 main() の処理を最後まで実行したら終了するという形態になって
いない。どこで何が実行されるのかわかりにくいかもしれないが早く慣れる。

main() で一通りの設定が終わったら最後に ros::spin(); に制御を渡して、
以後は、すべてタイマーによる周期的な関数の
呼び出しで処理が進んでいく。モータの動きを制御する処理の中心になるのは、
次に示す3個の関数である。
intelligence();
monitorJointState();
timerCallback();
それぞれが連携して、ロボットが持つすべての関節の動作が決まる。
現在のサンプルプログラムは、事前にプログラム中で記述した
一定の動きで関節を動かしているが、後にセンサが
使えるようになれば、センサからの情報でロボット周囲の状況を把握して、
それに対して何らかの働きかけをするプログラムを作成できるようになる。

行動計画 AI の計算 intelligence()、
モータ角度の検出 monitorJointState()、
モータの目標角度の指示 timerCallback()
は、現在はすべて1秒に100回実行される。
これらはすべてタイマーに登録されて、一定の時間間隔で実行されるように
なっている。タイマーを使用せずに記述した一般的なプログラムのイメージ
としては、次の形に近い。
while (TRUE) {
    monitorJointState(); // モータの角度を調べて
    intelligence();      // 次の行動（目標角度）を決めて
    timerCallback();     // モータに指示を送る
    sleep();             // 1秒に100回になるように時間待ち
}

上記のプログラムをROSのプログラムとして書くと次のようになる。
タイマーを使わない場合はこのようにも書ける。
ros::Rate rate(100); // 1秒に100回になるように設定
while (ros::ok()) {
    monitorJointState(); // モータの角度を調べて
    intelligence();      // 次の行動（目標角度）を決めて
    timerCallback();     // モータに指示を送る
    ros::spinOnce();	 // ROSの処理を1回行う
    rate.sleep();	 // 1秒に100回になるように時間待ち
}

ただし、実際の処理では 3 個の関数は同期しているわけではないので、
順番に実行されることは保証されない。
※  その後、ros::spin(); はマルチスレッドの実装の呼び出しに一旦変更
　されたが、OpenCV による画像処理で問題が生じたのでもとに戻された。

intelligence() から呼び出される UserMotion() 以降の処理で、様々な
動きを組み合わせて複雑な動作を実現する仕組みは、READMEprogramming.txt, 
READMEcall.txt で説明されている。

モータの制御の仕方

異なる動きを実現する、以下の３種類のモードが用意してある。
・シンプルな PID 制御の MODENONE 、
・プロファイルにより細かく目標角度を決める MODEPROFILE 、
・シンプルなプロファイルのMODEPROFILE2
がある。
・MODENONEは動きが速いが慣性で振られる動きが大きい。
・MODEPROFILEはゆっくり動くが、慣性で振られにくいという違いがある。
・MODEPROFILE2 はその中間で、プロファイルの前半は徐々に速度を上げ、
　後半はMODENONEと同じである。
同じ動きで3種類のモードで実際にどのような動きになるか、事前に試して
比較して確認しておくとよい。
モータ制御のパラメータを指定する部分で、選択したモードを指定する。
使う時には関節毎に目的に合った制御を選べばよい。

プロファイルの計算の仕方は、回転に要する時間 duration と、回転
させたい角度から 1/100 秒毎の目標角度を計算により求めておいて、
順次それを送信してゆっくりした動きを実現している。
特に、動き始めと動き終わりの回転速度を遅くすることで、
慣性による振れを少なくしている。
duration は初期値としてある値になっているが、変更して構わない。
ただし10秒を超えると現在はプロファイルの配列が不足する。対処は
配列のサイズを大きくすればよい。
また短い時間を指定すると、慣性で振られる動きが大きくなることが予想される。
短時間で動かしたい場合は MODENONE を指定する方が良い場合があるかも
しれない。

--------------------------------------------------------------

ロボットの構造

脚は合計で6本あり、脚1本につき肩から手首まで3関節、手首から先に3関節ある。
関節の回転軸は根本から、Z軸、X軸、X軸、手首から先はX軸、Y軸、Z軸(この3軸
の順番は要確認)、指の開閉は各指に1軸の回転を実現している。
脚、手首、指の構造と関節の定義は URDF ファイルに記述されている。

関節は脚6本とハンドで48個、首に2個、腹のハッチ用に2個、合計52個である。

自分で作るロボットのモデルは URDF に従って、自分で記述する必要がある。
その後、プログラムを作る時には、intelligence() で 1/100 秒周期でその時々
の関節の目標角度を設定してやれば、あとは残りの関数群が動かしてくれる。
